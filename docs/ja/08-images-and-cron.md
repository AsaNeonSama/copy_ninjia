このガイドでは、専用画像ライブラリの準備、コマンドによる画像の収集・抽選、および画像・アルバム・音声・Web ダイジェストの定時配信設定を解説します。JSON フィールドの完全な定義は [デプロイ設定説明](../../config_example/README/ja.md)、各コマンドの権限と詳細な挙動は [09 コマンドリファレンス](09-commands.md) を参照してください。

## 専用画像ライブラリの準備

`config/dynamic/assets.json` で画像ライブラリのディレクトリパスを設定します：

```json
{
  "onlyPath": {
    "random_h_image_dir": "./h_image"
  }
}
```

- **パス形式**：絶対パス、または `./`・`../` で始まる相対パス（実行時データルート `RUNTIME_DATA_ROOT` 基準で解決）を指定できます。データルートの詳細は [07 運用マニュアル](07-operations.md) を参照してください。
- **アクセス権限**：サービス実行ユーザーに読み取り・書き込み・走査権限（`rwx`）が必要です。未作成なら起動時に自動作成され、既存ディレクトリがある場合は全エントリが厳格に検査されます。
- **ファイル名規約**：配置できるのは**通常の画像ファイルのみ**で、ファイル名は画像バイナリの小文字 16 進 SHA-256 ハッシュ値（`RANDOM_IMAGE_CONTENT_NAME_PATTERN`）＋対応拡張子（`RANDOM_IMAGE_EXTENSIONS`）に一致している必要があります。サブディレクトリ・シンボリックリンク・規約外のファイル名が 1 つでもあると起動は拒否されます。
- **動的な追加・削除とキャッシュ同期**：
  - `/h_image add` コマンドまたは Mini App 画像庫から登録すると、自動的に SHA-256 ハッシュ計算と保存が行われます（同一ハッシュの既存画像は重複保存をスキップ）。
  - `/h_image add` や Mini App 画像庫経由の追加・削除はメモリキャッシュへ即時反映され、サービスの再起動は不要です。
  - ディレクトリへ手動で直接置いた画像は、サービス再起動（またはホットリロードでこのディレクトリへ切り替えた時点）までメモリキャッシュに入らず抽選・画像庫にも表示されません。手動削除した画像は、次回抽選または Mini App 画像庫の読み取り時に検知されてキャッシュから除外されます。

パス解決ルールの詳細は [assets.json](../../config_example/README/ja.md#assetsjson) を参照してください。

## 画像の収集と抽選

1. スーパー管理者が対象グループで `/init enable` を実行し、Bot を有効化します。
2. `isCanAddHImage` 権限を持つユーザーが画像メッセージに返信して `/h_image add` を送信します（対象メッセージがアルバムの一部である場合、Bot が受信済みの同一アルバム画像もまとめて登録されます）。
3. 返信される集計レシートで、新規保存・既存重複・サイズ超過・取得失敗の各件数を確認します。
4. グループメンバーが `/h_image` を送信すると、専用ライブラリから一様ランダムに 1 枚が抽選され、常に Telegram のスポイラーマスク付きで送信されます。

対応形式、容量・画素数上限、レート制限、および `COMMAND_MESSAGE_AUTO_DELETE_MS` による自動削除ルールは [ランダム画像コマンド](09-commands.md#random-images) を参照してください。

## 定時画像の送信

定時タスクは `config/dynamic/cron.json` のトップレベル配列で定義し、稼働中のホットリロードに対応しています。以下は毎日正午（`Asia/Tokyo`）に専用ライブラリのランダム画像を 1 枚送信する例です：

```json
[
  {
    "name": "daily-library-image",
    "chat_id": [-1001234567890],
    "cron": "0 12 * * *",
    "time_zone": "Asia/Tokyo",
    "actions": [
      {
        "type": "send_image",
        "payload": {
          "rand_image": true,
          "content": "今日のランダム画像",
          "is_blurred": true
        }
      }
    ]
  }
]
```

`chat_id` を実際のグループ ID に置き換え、実行時刻やキャプションを調整してください。タスク名 `name` はファイル全体で一意である必要があり、1 つのタスク内の `actions` は配列順に直列実行されます。

### 単画像・アルバム・ランダム画像

`send_image.payload` の画像ソース指定は以下の 4 通りに対応しています：

| 送信方式 | `send_image.payload` の画像指定方法 |
| :--- | :--- |
| **固定の単一画像** | `url: ["https://example.com/a.jpg"]`、または `path: ["./posters/a.jpg"]` |
| **固定のアルバム** | `url` または `path` の配列に複数の画像を指定 |
| **専用ライブラリからのランダム画像** | `rand_image: true`（`path` は省略） |
| **任意ディレクトリからのランダム画像** | `rand_image: true` とディレクトリ文字列（例：`path: "./gallery"`） |

- 固定画像モードでは `url` と `path` は排他であり、1 枚のみ送る場合も要素 1 つの配列で指定します。複数要素を指定すると Telegram のメディアグループ（アルバム）として一括送信されます。
- ランダムモード（`rand_image: true`）の `path` には単一のディレクトリ文字列を指定し、任意ディレクトリ内の画像には SHA-256 ファイル名規約（`RANDOM_IMAGE_CONTENT_NAME_PATTERN`）は適用されません。
- `is_blurred` でスポイラーマスクの有無を制御します（省略時は `false`）。

### 時刻と送信先

- **Cron 式とタイムゾーン**：`cron` には標準の 5 フィールド式または `@daily` 等のマクロを指定できます。`time_zone` には IANA タイムゾーン名を指定し、省略時は `config/static/bot.json` の `time_zone`（既定値 `DEFAULT_BOT_TIME_ZONE`）を継承します。
- **ランダム間隔スケジュール**：`rand_cron` に `[CRON_RANDOM_INTERVAL_MIN_MS, CRON_RANDOM_INTERVAL_MAX_MS]` 内の範囲（例：`"6h-12h"`）を設定すると、初回のみ `cron` に従い、以降は各実行完了時に指定範囲から一様ランダムに次回時刻を算出します（分単位に切り上げ）。プロセス稼働中に 1 回だけ実行する `just_once: true` とは同時指定できません。
- **配信先グループ**：`chat_id` には数値グループ ID 配列のほか、有効化済みかつ送信可能な全グループへ配信する `["all"]`（`CRON_ALL_CHATS`）、または特定グループを除外して一斉配信する `["except", -1001234567890]`（`CRON_EXCEPT_CHATS`）を指定できます。

## 定時音声とその他のアクション

定時音声を送るには、先に `config/dynamic/agent.json` で `agent.tts` を設定した上で、タスクの `actions` に `send_voice` を追加します：

```json
{
  "type": "send_voice",
  "payload": {
    "content": "おやすみ、また明日ね",
    "tone": "小声で"
  }
}
```

- **音声合成と再利用**：話者は `agent.tts.voice` が使用され、任意の `tone` で発話ニュアンスを指定できます。1 つのタスクで複数グループへ配信する場合、実行ごとに 1 回だけ音声を合成して余分な TTS クォータ消費を抑え、最初の送信成功で取得した Telegram の `file_id` を後続グループへの送信でそのまま再利用します（音声バイト列の再アップロードは行いません）。詳細は [デプロイ設定説明](../../config_example/README/ja.md#agentjson) を参照してください。
- **その他のアクション種別**：テキスト送信（`send_message`）、ファイル送信（`send_file`）、Web ページ取得＋AI 要約配信（`send_web_digest`）にも対応しています。各フィールド仕様や文字数上限は [cron.json](../../config_example/README/ja.md#cronjson) を参照してください。

## 動作確認と実行中の変更

- **事前チェック**：画像ディレクトリの権限、対象グループでの `/init enable` 実行状態、および Bot の発言権限を確認した上で、`/h_image add` と `/h_image` の動作をテストします。
- **スケジュール監視**：設定後はログでタイムゾーン解釈と次回実行予定時刻を確認し、予定時刻に対象グループへ配信されることを確認します。
- **動的ホットリロード**：`assets.json`・`cron.json`・`agent.json` は無停止でホットリロードされます。タスクは `name` 単位で突合され、未変更のタスクは既存のタイマーを維持したまま継続し、追加・変更されたタスクのみ次回時刻が再計算されます。起動時バリデーション・トピック配送・停止時ドレインの詳細は [04 実行時の正式な不変条件](04-invariants.md)、旧画像ライブラリの移行手順は [07 運用マニュアル](07-operations.md) を参照してください。
